## 2. リストパーツで改善されること／**AI-2はリストを読まない（決定的）**

社長のご質問「リストで何が改善されるのか」「AI-2はリストの中身を拾えるのか」は、**セットで答えるべき論点**でした。調査結果は以下です。

### (1) AI-2（SharePoint agent）はリストのデータを使わない — 公式明記
> **"Agents currently don't use data from Lists."**（Copilot in SharePoint 公式FAQ）

- SharePoint agentがナレッジ源にできるのは **サイト／ドキュメントライブラリ／フォルダ／ファイル**。**リストは対象外**です（V15）。
- つまり**リストに資料リンクを入れると、AI-2の回答には出てきません**。
- 補足（正直な注記）: 同じFAQに「Site Pagesライブラリをソースとして個別指定はできない」ともあります。**サイト全体をソースに選べばページは対象**になりますが、この但し書きは実装時に確認が必要です。
- ※混同注意: 「SharePointがリスト対応」という情報は、**別機能のAgent Builder（リスト1つまで可）やCopilot Studio（対応）**の話です。今回のAI-2＝SharePoint agentは非対応（V15-3）。

### (2) リストの利点（何が改善されるか）
| | リスト web part | テキスト web part |
|---|---|---|
| カテゴリ/言語での**絞り込み・並べ替え** | ○（ビュー・列フィルター） | ×（手作業の見出し分けのみ） |
| 件数が増えた時の**管理のしやすさ** | ○（列で構造管理） | △（本文が長くなる） |
| **人間のサイト内検索**でヒット | ○（既定でインデックス対象・V14） | ○ |
| **AI-2（生成AI）が回答根拠にできる** | **×（対象外）** | **○（ページ本文として）** |

### (3) 結論・推奨
- **AI-1,2の実装がマスト要件**である以上、**資料リンクはAI-2が拾えるページ本文（テキストパーツ）に置くべき**——これが今回の調査の核心です。
- → WF v5では**クライアント公開資料を「テキストパーツ」を主案**に変更しました（カテゴリ見出し＋リンク箇条書き、30本超のお役立ち資料はセクション折りたたみで格納）。
- **失うもの（正直に）**: カテゴリ/言語での動的な絞り込み・並べ替えができなくなります。
- **副案としてリスト併用**もWFに点線で併記しました（人間のサイト内検索・一覧管理には有効）。**主案=テキストパーツ／副案=リスト併用**、どちらを採るか社長のご判断を仰ぎます。
- 将来リストがSharePoint agentのナレッジ対象になれば見直す価値があります（非公式情報では対応の兆しあり・一次情報では未確認）。

## 4. KPI → **社長は検索レポートを見られません。組み替えます**

ご指摘のとおりでした。権限を確認した結果:

| レポート | 必要権限 | 社長（サイト所有者）は見られるか |
|---|---|---|
| **Site usage**（ページ別閲覧数・一意閲覧者・人気コンテンツ・滞在時間） | **サイト管理者・所有者・メンバー・訪問者**（公式明記） | **○ 見られます** |
| **Search usage reports**（ゼロ件検索・人気クエリ・放棄クエリ） | **サイトコレクション管理者のみ**（"Only site collection admins can view search reports data."） | **× 見られません** |

### 組み替えたKPI案
**A. 社長ご自身で取れる指標（Site usage・主軸にする）**
1. **主要ページの閲覧数・一意閲覧者数**（ブランドライブラリ、キャンディデート等）— 刷新前後で比較
2. **人気コンテンツ**（どの資料/ページが実際に使われているか）
3. **平均滞在時間**（探索コストの目安。ブランドライブラリの長時間滞在＝迷いの疑い）
4. **サイト全体の訪問数・利用者数の推移**

**B. 管理者への依頼が必要な指標（依頼できる場合のみ）**
5. **ゼロ件検索・人気検索語**（＝「見つからない」の直接的な証拠）→ **サイトコレクション管理者に月次でExcelエクスポートを依頼**する運用を提案します。権限付与が可能ならそれが最善です。

**C. 権限不要の手動指標（補完）**
6. **マーケ部への「資料が見つからない」問い合わせ件数**（手動集計）
7. **AI-1/AI-2の利用状況・ブランドレビュー申請数**（Lists/Formsの件数集計）

→ **主軸をA（社長が自分で取れる）に置き、Bは「取れれば強力な補強」**という設計に変更します。空振り率をKPIの中心に据える前提は撤回します。
