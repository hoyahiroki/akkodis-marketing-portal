一次情報: learn.microsoft.com, support.microsoft.com（Microsoft公式ドキュメント）を中心に確認。ブログ等の二次情報は「傾向の裏取り」用途のみで使用し、本文では一次情報を優先して明記した。

## 0. 結論サマリー（先に要点）

| 機能 | 推奨実装方式 | 理由 |
|---|---|---|
| **AI-2（サイト内Q&A・出典付き）** | **SharePointの「エージェント」機能（SharePoint agent）を第一候補**。ナレッジ範囲を厳密にサイト横断/複数サイトにしたい・変数でスコープ制御したい等の高度要件が出たら**Copilot Studioのカスタムエージェント**に格上げ | サイト所有者・編集権限があれば自分で作れる。ユーザーのアクセス権範囲でしか回答しない権限境界が標準装備、引用（出典）も標準機能 |
| **AI-1（PPT/画像アップロード→ブランド準拠判定）** | **Copilot Studioのカスタムエージェント（会話内ファイルアップロード＋画像入力分析機能）が必須**。SharePoint agentは画像非対応（対応予定のみ）で実現不可 | SharePoint agentは現時点で画像ファイルをナレッジ/添付として扱えない。Copilot Studioの「ファイルアップロード」機能ならJPG/PNG/WebP/GIFの画像を会話内で解析できる。ただしPPTXの直接アップロードは実験的機能扱いで要Microsoft申請、色のΔE数値照合のような厳密判定はできず「AIの目視相当の指摘」に留まる（後述5章） |

**権限の切り分け（最重要）**:
- **サイト所有者だけでできる**: SharePoint agentの作成・公開・ナレッジ選定、Copilot Studioでの基本的なエージェント試作（Microsoft 365 Copilotライセンスがあれば）。
- **テナント管理者への確認が必須**: (1) Microsoft 365 Copilotライセンスの割当・Pay-as-you-go課金の設定、(2) Copilot Studioの作成者権限(Copilot Studio Authors)付与状況、(3) DLP/機密ラベルでエージェントの参照除外設定、(4) SharePoint Advanced Managementでのアクセス制御方針、(5) Graph connector（外部データ取り込み）の登録可否、(6) Copilot Studioエージェントの公開・共有ポリシー（テナント全体への公開可否）。

## 1. 実装方式の選択肢と違い

### (a) SharePointの「エージェント」（SharePoint agent／サイトスコープCopilot）

- SharePointサイト内の「新規」→「エージェント」、ドキュメントライブラリの「AIアクション」、またはファイル右クリックから作成する**宣言型（declarative）エージェント**。GUIのみで完結し、コード不要。
- ナレッジソースはそのサイトの**サイト、ページ、ドキュメントライブラリ、個別ファイル**。作成時にスコープ（サイト全体 or 特定ファイルのみ）を選べる。
- ユーザーがサイト訪問時に「エージェント」アイコンから会話でき、サイト所有者は「メインエージェント」を1つ指定できる。
- 回答は必ずユーザー自身のアクセス権範囲に限定される（後述6章）。
- **画像・PPT等のマルチモーダル入力には非対応**（現状のサポートファイル形式はDOC/DOCX/PPT/PPTX/XLSX/FLUID/LOOP/PDF/TXT/RTF/ASPX/HTM/HTML/ODT/ODP等のテキスト系文書のみ。画像・会議録画・OneNoteは「対応予定」と明記されており現時点未対応）。
- 出典: [Create an agent in SharePoint](https://support.microsoft.com/en-us/sharepoint/copilot-in-sharepoint/create-an-agent-in-sharepoint), [Manage access to agents in SharePoint](https://learn.microsoft.com/en-us/sharepoint/manage-access-agents-in-sharepoint), [FAQ about Copilot in SharePoint](https://support.microsoft.com/en-us/office/frequently-asked-questions-about-copilot-in-sharepoint-eb1b7668-3d98-4a93-98ef-f0c6dfc694f0)

**→ AI-2に最適**（サイト内資料Q&A・出典付き・権限境界が標準）。**AI-1には不適**（画像非対応）。

### (b) Microsoft Copilot Studio のカスタムエージェント

- ローコードのエージェントビルダー。トピック（会話フロー）、ナレッジソース（SharePoint/OneDrive/アップロードファイル/Graph connector等）、ツール（コネクタ、Power Automate連携）、プロンプト（生成AIツール）を組み合わせて構築。
- **会話内でのファイル/画像アップロード分析**機能があり（Generative AI設定 → File processing capabilities → File uploads）、JPG/PNG/WebP/非アニメーションGIF、DOCX/CSV/PDF/TXTに対応。**PPTX/XLSXは現時点で実験的（experimental）機能扱いで、利用にはMicrosoft担当者/サポートへの申請が必要**と明記されている。
- SharePointを本格的なナレッジソースとして追加可能（サイトURL/リストの両方に対応、フィルタ条件・変数によるスコープ制御あり）。ユーザー認証はMicrosoft認証がデフォルトで、ユーザーのアクセス権範囲でしか応答しない設計。
- 公開先（チャネル）はTeams、カスタムWebサイト（iframe埋め込み）、SharePointチャネル、Facebook等、多岐にわたる。
- 出典: [Add SharePoint as a knowledge source](https://learn.microsoft.com/en-us/microsoft-copilot-studio/knowledge-add-sharepoint), [Allow file input from users](https://learn.microsoft.com/en-us/microsoft-copilot-studio/image-input-analysis), [Upload files as a knowledge source](https://learn.microsoft.com/en-us/microsoft-copilot-studio/knowledge-add-file-upload), [Declarative Agents vs Copilot Studio 比較](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/declarative-agent-tool-comparison)

**→ AI-1に必須**（画像分析の唯一の現実的な選択肢）。**AI-2にも使えるが**、SharePoint agentより構築の手間とライセンス/課金の考慮点が増える（3章）。

### (c) Microsoft 365 Copilot（Copilot Chat本体）

- Word/Excel/PowerPoint/Teams/Outlook等に組み込まれたCopilot本体。チャットに直接ファイルを添付でき（「コンテンツを追加」機能）、Word/Excel/PowerPoint/PDFの要約・表抽出・データ分析・質問応答が可能。画像入力にも対応（Vision Q&A的な用途）。
- ただし「サイトにスコープしたエージェント」「特定ガイドラインへの照合ロジック」を組み込む仕組みではなく、**カスタムのルール定義・永続的なナレッジ紐付けを行う器としては不向き**。宣言型エージェント（declarative agent）を作ってM365 Copilotに組み込むことは可能だが、これは実質(a)や(b)の応用形（Agent Builder／Teams Toolkit等での構築）であり、単体の「Copilot Chat機能そのもの」はAI-1/AI-2の恒久的な実装先としては選ばない。
- 出典: [Agents for Microsoft 365 Copilot](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/agents-overview), [Analyze images and documents with Copilot (Microsoft Learn Training)](https://learn.microsoft.com/en-us/training/modules/boost-productivity-with-copilot/6-image-document-analysis-with-copilot)

## 2. SharePointページ/サイトへの配置方法

### AI-2（SharePoint agent方式・推奨）
1. 対象サイトのホームページで「新規」→「エージェント」、または既存の「AIアクション」→「エージェントを作成」からナレッジ（対象ドキュメントライブラリ、マーケ資料フォルダ、申請フローページ等）を指定して作成。
2. サイト所有者が「メインエージェント」として設定すると、サイト全体のグローバルヘッダーの「エージェント」アイコンから誰でも開ける状態になる。
3. カスタムエージェントは`.agent`ファイルとしてSite Assets > Copilots等に保存され、Word/Excelファイルと同様にリンク共有も可能。
- 出典: [Manage access to agents in SharePoint](https://learn.microsoft.com/en-us/sharepoint/manage-access-agents-in-sharepoint), [Create an agent in SharePoint](https://support.microsoft.com/en-us/sharepoint/copilot-in-sharepoint/create-an-agent-in-sharepoint)

### AI-1（Copilot Studio方式）
配置方法は3系統あり、**用途に応じて選ぶ必要がある（重要な制約あり）**:

1. **SharePointチャネルへのネイティブ公開**: Copilot Studioの「チャネル」→「SharePoint」からサイトを選び「デプロイ」。「承認済み」にするとサイトの「承認済み」セクションに表示される。
   - **重要な制約**: 公式ドキュメントに明記の通り、**「SharePointチャネルに公開したエージェントはユーザーがファイルをアップロードできない」**。したがってAI-1（画像/PPTアップロードが必須機能）を**この方式で置くことはできない**。
2. **カスタムWebサイトチャネル（iframe埋め込み）**: Copilot Studioの「カスタムWebサイト」チャネルで発行されるHTML埋め込みコードを、SharePointページの「埋め込み（Embed）」Webパーツに貼り付けて表示。ファイルアップロードは「Custom website」チャネルでサポート対象のため、**AI-1はこの方式で配置する**。ただし埋め込み時は認証方式を「認証なし（no authentication）」にする必要がある点に注意（＝匿名アクセス相当になるため、社内限定公開にする場合はサイトの権限設計・ネットワーク制御と組み合わせる必要がある。要管理者確認）。
3. **Teams/M365 Copilot Chat経由**: Teamsチャネルに公開し、Teamsタブやチャットからアクセスさせる。ファイルアップロード対応チャネルの一つ。SharePointページからは「Teamsで開く」リンクを貼る形になる。
- 出典: [Publish an agent to SharePoint](https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-add-bot-to-sharepoint), [Publish an agent to a live or demo website](https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-connect-bot-to-web-channels), [Allow file input from users（対応チャネル一覧）](https://learn.microsoft.com/en-us/microsoft-copilot-studio/image-input-analysis)

### ワークフローへの組み込み案（具体）
- **マーケ資料ポータルのサイトトップページ**: 「メインエージェント」としてAI-2（SharePoint agent）を設定 → 訪問者は常設の「エージェント」アイコンから「◯◯の資料はどこ？」等を質問可能。
- **「ブランドガイドライン申請」専用ページ（新設 or 既存の申請ページ）**: Embed Webパーツ経由でAI-1（Copilot Studioエージェント、カスタムWebサイトチャネル）を設置し、「ここにPPT/画像をドラッグ＆ドロップして準拠チェック」というアップロードUIを提供。
- 両者は別エージェントとして分離するのが妥当（用途が「文書検索QA」と「ファイル解析＋ルール照合」で全く異なるため、1つのエージェントに無理に統合すると精度が落ちる）。

## 4. 作成に必要な権限 — 「所有者ができること」と「管理者に確認すべきこと」

### 4-1. サイト所有者(owner)/編集権限だけで完結する範囲

- SharePoint agentの新規作成・編集・ナレッジソース（サイト内ファイル/ページ）の指定。
- サイトの「メインエージェント」の選定。
- `.agent`ファイル単位でのリンク共有（誰が使えるかの制御）。
- Copilot Studioで**既にテナントとしてライセンス/権限が用意されている前提**なら、エージェントの試作・トピック設計・SharePointナレッジソースの追加・ファイルアップロード機能のON設定。
- 出典: [Create an agent in SharePoint](https://support.microsoft.com/en-us/sharepoint/copilot-in-sharepoint/create-an-agent-in-sharepoint), [Manage access to agents in SharePoint](https://learn.microsoft.com/en-us/sharepoint/manage-access-agents-in-sharepoint)

### 4-2. テナント管理者への確認・許可が必要な範囲

1. **Microsoft 365 Copilotライセンスの割当有無**: 自分と利用対象者にM365 Copilotライセンスが付与されているか。無ければ管理者による購入・割当が必要。
2. **Pay-as-you-go課金の設定**: ライセンスなしでの少人数利用を想定するなら、Global管理者/SharePoint管理者がAzureサブスクリプション(Owner/Contributor)と紐づけて設定する必要がある。出典: [Set up SharePoint agents for pay-as-you-go billing](https://learn.microsoft.com/en-us/sharepoint/sharepoint-agents-azure-billing)
3. **Copilot Studioの利用契約・作成者権限**: テナントがCopilot Studioの契約（Copilot Creditパック）を持っているか。持っていない場合、無償の「Copilot Studioユーザーライセンス」は発行されない。また「Copilot Studio Authors」ロールの設定（Power Platform管理センター）は管理者作業。出典: [Copilot license for creating AI Agents for SharePoint & Copilot Studio (Microsoft Q&A)](https://learn.microsoft.com/en-us/answers/questions/2223343/copilot-license-for-creating-ai-agents-for-sharepo) （**要確認**: 回答フォーラム記事のため、貴テナントの実運用は管理者に一次確認を推奨）
4. **DLP（データ損失防止）ポリシーとエージェントへの適用**: Copilot Studioエージェントに対するDLPは既定で強制されていないため、テナント管理者がPower Platform管理センターでポリシーのスコープ（テナント全体/環境単位）を設定する必要がある。ブランドガイドライン文書や機密資料をAI-1/AI-2の対象から除外したい場合は、この設定を管理者に依頼。出典: [Configure data policies for agents](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-data-loss-prevention)
5. **機密ラベル×DLPによる参照除外**: SharePoint側でも、Microsoft Purview DLPカスタムポリシー（「機密度ラベルを含む」条件）でエージェントの参照から特定ファイルを除外できる。この設定・ポリシー管理はコンプライアンス管理者/SharePoint管理者の権限範囲。出典: [Manage access to agents in SharePoint（Purview DLP節）](https://learn.microsoft.com/en-us/sharepoint/manage-access-agents-in-sharepoint)
6. **SharePoint Advanced Management（制限付きアクセス制御・制限付きコンテンツ検出）**: サイト単位でCopilot/エージェントからの参照を遮断する高度な制御は、SharePoint管理者がSharePoint Advanced Management機能（追加ライセンスが必要な場合あり・**要確認**）で設定。出典: 同上
7. **Graph connectors（外部データの取り込み）**: AI-2で社内Wiki・外部ツール等もナレッジにしたい場合、Microsoft 365管理センターの「検索とインテリジェンス→データソース」でGraph connectorを登録・有効化する必要があり、これはテナント管理者の作業。出典: [Copilot connectors overview](https://learn.microsoft.com/en-us/microsoft-365/copilot/connectors/overview)
8. **Copilot Studioエージェントの公開・共有ポリシー**: テナント全体への公開、外部チャネル（カスタムWebサイト等）への発行可否は、環境レベルのガバナンス設定に依存する場合がある。特にカスタムWebサイトチャネルは「認証なし」を要求するため、社内向け限定公開が意図と異なる形（誰でもアクセス可能なURL）になっていないか、公開前に管理者・情報セキュリティ担当とネットワーク/リンク共有範囲を確認すべき。出典: [Publish an agent to a live or demo website](https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-connect-bot-to-web-channels)
9. **Copilot Studioエージェントの利用量上限・PPTX実験的機能の申請**: AI-1でPPTXを直接アップロードしたい場合、Microsoft担当者/サポートへの実験的機能の有効化申請が必要（テナント管理者経由での申請が想定される）。出典: [Allow file input from users](https://learn.microsoft.com/en-us/microsoft-copilot-studio/image-input-analysis)

## 5. AI-1の実現可否と限界

### 実現方式
- Copilot Studioカスタムエージェントで、会話内ファイルアップロード（画像入力分析機能）をONにし、ブランドガイドラインをナレッジソース（PDF化した規定文書等）として登録。ユーザーがPPT（PDF変換 or 画像化して）または画像をアップロードすると、生成AIモデルがガイドライン文書と照合してテキストで所見を返す、という構成が現実的な最大公約数。
- 出典: [Allow file input from users](https://learn.microsoft.com/en-us/microsoft-copilot-studio/image-input-analysis), [Upload files as a knowledge source](https://learn.microsoft.com/en-us/microsoft-copilot-studio/knowledge-add-file-upload)

### 制約・限界（重要）
1. **PPTXの直接アップロードは実験的機能**。安定運用するには「PPTをPDFにエクスポートしてからアップロード」という前段の変換ステップを業務フローに組み込むのが現実的（Microsoft公式でも当面の回避策としてこの構成が想定される）。
2. **画像は最大15MB、テキスト抽出は文字数上限（コード インタープリタ無効時は1ファイルあたり/合計3万文字）** の制約があり、大量スライドのPPTでは分割が必要になる場合がある。
3. **色・ロゴの厳密判定（RGB/ΔE数値照合、ロゴの改変検出、最小サイズ/クリアスペース違反の픽셀単位検出等）は、Copilot Studioの標準機能だけでは保証できない**。Copilot Studioは汎用のマルチモーダル言語モデルによる「目視・文脈判断」であり、専用の画像認識パイプライン（色のハードコード比較、ロゴのテンプレートマッチング等）を持たない。市場のブランド準拠専用ツール（外部SaaS）は色のΔE許容誤差設定・専用の画像認識モデルを組み合わせて高精度化しているが、これはCopilot Studio標準では未サポートの領域であり、**厳密な自動判定が必要なら「低信頼度のケースは人間レビューに回す」設計、または将来的にAI Builder（Azure AI Vision/Document Intelligence）とのagent flow連携で補強する拡張案**が必要（この拡張は追加のAI Builder/Azure課金・設定が発生するため要管理者確認・別途提案が必要）。
4. **禁止画像・AI生成画像ルールの判定**は、モデルの一般知識・与えたガイドライン文章に依存した確率的な判断になり、100%の検出率は期待できない。「違反の可能性を提示し、最終判断は人間が行う」運用前提が現実的。
5. 結論として、**AI-1は「一次スクリーニング（見落とし防止・気づきの提示）」としては十分実用的だが、「最終承認の自動化」として運用するのはリスクが高い**。品質保証プロセス（人による最終確認）を残すことを推奨。

## 6. AI-2の精度前提

### 権限境界（ユーザーがアクセス権を持つ範囲でのみ応答）
- SharePoint agent、Copilot StudioのSharePoint知識ソースいずれも、**ユーザー自身のMicrosoft 365権限（最低でも対象サイト/リストへのRead権限）でセキュリティトリミングされる**。ユーザーがアクセス権を持たないサイト/ファイルの内容は回答に含まれない。
- Copilot StudioでSharePointを知識ソースにする場合、既定の「Authenticate with Microsoft」認証を使うことで、この権限境界を自動的に引き継ぐ。手動で認証方式を変える場合は、Entra ID アプリ登録で`Sites.Read.All`と`Files.Read.All`スコープを正しく設定する必要がある（設定を誤ると全ユーザーが同一の過剰な権限で検索されるリスクがあるため、この設定変更はテナント管理者と要相談）。
- 出典: [Add SharePoint as a knowledge source](https://learn.microsoft.com/en-us/microsoft-copilot-studio/knowledge-add-sharepoint), [Manage access to agents in SharePoint](https://learn.microsoft.com/en-us/sharepoint/manage-access-agents-in-sharepoint)

### 出典（引用）の付与
- SharePoint agent、Copilot StudioのSharePoint/ファイルナレッジソースとも、生成回答に対して参照元ファイル/ページへの**引用（citation）リンクが標準で付与される**設計になっている。DLP/機密ラベルにより内容の利用が禁止されている場合でも「引用として識別はされるが、内容は回答に使われない」という挙動になる点は運用上の注意点（＝「該当資料はあるが中身は出せない」という半端な回答になり得る）。
- 出典: [Manage access to agents in SharePoint（Purview DLP節）](https://learn.microsoft.com/en-us/sharepoint/manage-access-agents-in-sharepoint)

### ハルシネーション対策
- Copilot Studioでは「Use general knowledge（一般知識の利用）」設定をOFFにし、ナレッジソース以外からの回答（Web検索含む）を無効化することで、指定ナレッジ外の情報を使った回答を防止できる（該当情報が無い場合は「no response」で応答）。
- ナレッジソースに「詳細な説明」を付与すること（generative orchestrationの精度向上のため）、フィルタ条件（更新日・作成者等）で参照範囲を絞ることも、精度・回答関連性の向上に有効な標準機能として提供されている。
- 出典: [Add SharePoint as a knowledge source（Filter節）](https://learn.microsoft.com/en-us/microsoft-copilot-studio/knowledge-add-sharepoint)
