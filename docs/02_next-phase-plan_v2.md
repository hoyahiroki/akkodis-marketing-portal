# AKKODiS 社内マーケティングポータル リニューアル ― 次フェーズ着手案（改訂版 v2）

**種別**: 社長提出用・提案ドラフト（外部非公開）／ **前提**: SharePoint サイト実装マスト
**位置づけ**: 本書は提案・下書きです。デプロイ・費用発生・外部公開の判断は行いません（該当は §7 に集約）。

## 1. エグゼクティブサマリ

差戻し理由「マーケティングポータルは **SharePoint サイトで実装するのがマスト**」を受け、方針を次のとおり転換した。

- **「AI機能ありき」から「SharePoint 既存パーツ（OOB）で作れるものありき」へ優先順位を反転**。まず標準 web part・リスト・ライブラリ・Microsoft Search で成立する構成を土台に据え、それを超える機能は L1〜L4 の実装階層を明示して、費用・ライセンス・ガバナンスの社長判断事項として切り出す。
- **最重要3課題は大半が L1（既存パーツ）で着手可能**という見立て。特に最優先のクイックウィン（キャンディデート資料の直リンク化）はクイックリンク web part で即実装でき、費用ゼロ・PoC不要で先行できる。
- **AIネイティブ6機能の多くは L2（Power Platform / Copilot / SharePoint Premium）以上**に該当し、追加ライセンスと管理者ポリシーが前提になる。これらは「やる/やらない」ではなく「テナントの実ライセンスを棚卸ししてから範囲を確定する」対象。
- **本書の SharePoint 機能名・パーツ名は知識カットオフ（〜2026年1月）時点の一般知識に基づく推定を含む**。外部Web遮断中のため最新確認ができない。各構成要素に**確度ラベル**を付し、**テナントの実ライセンスと SharePoint 管理者ポリシーで要検証**とする。断定はしない。

結論: **L1中心のMVPを最短で立ち上げ、L2以上のAI機能はライセンス棚卸し結果に応じて段階投入する**。次フェーズの最初の仕事は「作ること」ではなく「テナントで何が使えるかを確定すること」。

## 2. 確定スコープと前提

**最上位前提（今回追加・不変）**
- **① マーケティングポータルは SharePoint Online サイトとして実装する（マスト）。**
- **② 既存パーツ（OOB / L1）で作れることを最優先**。L2以上は実装階層を明示し社長判断に上げる。

**引き継ぐ確定事項（維持）**
- 刷新スコープ = **マーケティングポータル単体**。全社ポータル統合・SFDC 連携は**対象外**。
- 用語定義: 「組織図」= マーケ部の組織体制／「会社案内」= クライアント配布用PDF／SFDC指摘 = 対象外。
- 課題 **21件**（トップ4／ブランド7／クライアント3／キャンディデート2／パートナー2／横断3）。
- **最重要3課題**: ①ブランドライブラリの情報過多・ページ内ナビ欠如（最多利用319名）／②ポータル内検索性の弱さ（見つからない→メール問合せ）／③キャンディデート資料に直リンク無し（クイックウィン）。
- **AIネイティブ提案6機能**: ①ブランドセルフチェッカー（社長指定）②マーケ特化AIアシスタント（社長指定）③AI検索＆ファセット ④ガイドライン統合ナレッジ＋AI要約 ⑤申請フローAIウィザード ⑥AIメタデータ自動付与。

**留意（知識ベースの前提リスク）**
- Viva Topics は提供終了方針が示されていた認識（要確認）。ナレッジ統合は Viva Topics 前提にせず、ドキュメントライブラリ＋メタデータ＋Copilot要約で設計する。
- 「Syntex」は「SharePoint Premium」へ改称された認識。本書は SharePoint Premium 表記に統一。

## 3. SharePoint 実装マッピング（最重要セクション）

各機能を **想定構成要素 / 実装階層 L1〜L4 / 必要ライセンス目安 / 確度** で整理する。**構成要素の存在・名称・機能範囲は知識ベース推定を含み、テナントの実ライセンスと管理者ポリシーで要検証。**

| # | 機能 | 想定する SharePoint 構成要素 | 実装階層 | 必要ライセンス目安 | 確度 |
|---|---|---|---|---|---|
| QW | **キャンディデート資料の直リンク化（クイックウィン）** | クイックリンク／リンク web part、ドキュメントライブラリの共有リンク、ハイライトされたコンテンツ web part | **L1** | 標準 M365（追加なし） | **高** |
| 3-a | **AI検索（基本）** ＝課題②対策 | Microsoft Search（テナント標準の意味検索）、検索ボックス web part、ハイライトされたコンテンツ web part（動的クエリ） | **L1** | 標準 M365 | **高** |
| 3-b | **ファセット／絞り込み検索（高度）** | PnP Modern Search（コミュニティ製SPFx。ファセット・リファイナー）。標準の代替として Microsoft Search 縦棒/リファイナー | **L3**（PnP採用時）／一部 L1 | 標準（ただしカスタムコード許可が前提） | **中** |
| 6 | **AIメタデータ自動付与** | SharePoint Premium（旧Syntex）の文書理解モデル／自動分類、コンテンツタイプ＆メタデータ列 | **L2** | SharePoint Premium（従量 or 追加ライセンス） | **中〜高** |
| 4 | **ガイドライン統合ナレッジ＋AI要約** | ドキュメントライブラリ＋メタデータ（L1土台）、ページ、Microsoft 365 Copilot による要約 | **L1＋L2** | 要約部分に M365 Copilot | **中** |
| 2 | **マーケ特化AIアシスタント**（社長指定） | SharePoint サイトにスコープした Copilot エージェント（SharePoint agent）／Copilot Studio エージェント | **L2** | M365 Copilot ／ Copilot Studio（追加ライセンス） | **中** |
| 1 | **ブランドセルフチェッカー**（社長指定） | Copilot Studio エージェント（ブランドライブラリをナレッジ源にルール判定）／高度化時は SPFx UI | **L2**（高度化で **L3**） | Copilot Studio ＋ 場合により M365 Copilot | **低〜中** |
| 5 | **申請フローAIウィザード** | 基本申請＝Microsoft Lists＋Forms（L1）、フロー＝Power Automate、UI＝Power Apps、対話UI＝Copilot Studio | **L1（受付）＋L2（自動化・対話）** | Power Platform（プレミアムコネクタ時は追加）／Copilot Studio | **中** |

**ポータル基盤（前提レイヤ）**
- サイト = **コミュニケーションサイト**（閲覧中心の全社配信に適合）: **L1 / 確度 高**。
- 玄関体験 = **Viva Connections**（ダッシュボード/フィード。Teams・モバイル導線）: **L1〜L2 / 確度 中**（ライセンス範囲要確認）。
- ページ内ナビ（課題①対策）= セクションアンカー、ページ内リンク、目次的なクイックリンク配置: **L1 / 確度 高**。

**マッピングの含意**: 課題直結の土台（検索・ナビ・直リンク・ライブラリ再設計）は **L1で成立**。AI6機能は **概ね L2以上**で、ライセンス依存。**L4（SharePoint単体で不可）に分類される機能は現時点で無い**が、③高度ファセットと①高度チェッカーは **L3（カスタム開発・カスタムコード許可前提）** に落ちる可能性がある。

## 4. 改訂した優先度づけ（MoSCoW再整理）

**L1で実現できるものを上位、L3/L4は後回しまたは代替案**という原則で再配列。

| 優先 | 項目 | 階層 | 位置づけ |
|---|---|---|---|
| **最優先** | QW: キャンディデート資料の直リンク化 | L1 | **Must**。費用ゼロ・PoC不要で先行着手 |
| 高 | ブランドライブラリ再構成＋ページ内ナビ（課題①） | L1 | **Must**。最多利用319名への効果最大 |
| 高 | Microsoft Search 基本＋検索/ハイライト web part 設置（課題②） | L1 | **Must** |
| 高 | ライブラリのメタデータ列・コンテンツタイプ設計 | L1 | **Must**（後続のAI機能・検索・自動付与の土台） |
| 中 | 申請の Lists＋Forms 化（受付部分） | L1 | **Should**。自動化(L2)は次段 |
| 中 | ガイドライン統合ナレッジ（ライブラリ＋メタデータ） | L1 | **Should**。AI要約(L2)は後付け |
| 中 | AIメタデータ自動付与（SharePoint Premium） | L2 | **Could**（ライセンス確認後）。手動メタデータで代替可 |
| 中 | マーケ特化AIアシスタント（SharePoint/Copilot Studio agent） | L2 | **Could**（Copilot系ライセンス確認後） |
| 低 | 高度ファセット検索（PnP Modern Search） | L3 | **Could/Won't（今回）**。代替=Microsoft Search 標準リファイナー |
| 低 | ブランドセルフチェッカー高度版 | L2→L3 | **Won't（今回）**。まず「ガイドライン参照＋Copilot Q&A」で代替 |
| 保留 | 申請フローの対話AIウィザード | L2 | **Won't（今回）**。まず定型フォームで運用 |

**代替案の考え方**: L3/L2が要る機能は、**まずL1の簡易版で価値を出し、ライセンス確定後に段階的に置換**する（例: 高度ファセット→標準リファイナー、AIチェッカー→ガイドライン集約＋Copilot問い合わせ）。

## 6. 非機能・データ・権限・ガバナンス（SharePoint文脈）

- **サイト権限/共有**: コミュニケーションサイトは閲覧者中心。編集は担当グループに限定。外部共有は既定オフを推奨（クライアント配布PDFの扱いは §7 で判断）。
- **Microsoft Search のクロール範囲**: 検索対象を当ポータルサイトに適切にスコープし、機微/下書きコンテンツを検索面に露出させない。管理プロパティ/リファイナーの整備が検索性(課題②)の要。
- **Copilot / AI の情報境界とライセンス**: Copilot 系は「ユーザーがアクセス権を持つ範囲」を前提に応答する認識（要確認）。権限設計の誤りがそのままAIの情報漏れになるため、**F2の権限設計がAI機能の前提条件**。ライセンス保有者のみ機能が有効。
- **機微情報の分離**: クライアント配布用PDF・社外秘資料は専用ライブラリ＋権限分離。AIナレッジ源に含めるか否かを明示制御。
- **監査ログ**: M365 監査ログ／サイトアクセス記録の活用範囲を確認。SharePoint Premium 等の従量課金機能はコスト監視対象。
- **ガバナンス総括**: L2以上は**ライセンス・データ境界・コストの三点セットで管理者承認が必須**。L1中心設計は、この管理負荷を最小化する狙いも兼ねる。

## 7. リスクと未決事項（社長判断）

- **【要判断】L1範囲の確定とPoC対象**: MVPを「クイックウィン＋ブランドライブラリ再構成＋Search＋メタデータ」のL1 4点に絞り先行するか。（推奨: 絞る）
- **【要確認】テナントのライセンス実態**: M365 Copilot／Copilot Studio／SharePoint Premium（旧Syntex）／Power Platform プレミアムの保有・付与範囲。**これが未確定だとAI6機能の可否が決まらない**（最大のブロッカー）。
- **【要確認】カスタムコード(SPFx)許可**: テナントでカスタムコード配置が許可されているか。不許可なら高度ファセット(PnP Modern Search)等の **L3は選択肢から除外**され、L1代替で設計する。
- **【要確認】SharePoint管理・IT窓口**: 承認・設定変更を担う管理者/IT部門の特定。F0の前提。
- **【要判断】L2/L3が要る機能のコスト**: AI自動付与・Copilotアシスタント等の追加ライセンス費。費用対効果を見て採否。
- **【リスク】知識ベース推定**: 本書のパーツ名・機能範囲は〜2026年1月時点の推定。名称改称・提供終了（例: Viva Topics）・仕様変更の可能性があり、**F0での実機確認まで確定情報として扱わない**。
- **【要判断】クライアント配布PDF・外部共有方針**: 外部共有可否とセキュリティ要件。

## 8. 次アクション（3〜5個）

1. **SharePoint管理者/IT窓口を特定**し、テナント設定・承認ルートを確認する（社長→IT部門）。
2. **テナント機能・ライセンス棚卸し（F0）**: M365 Copilot／Copilot Studio／SharePoint Premium／Power Platform／SPFxカスタムコード許可の有無を一覧化する。
3. **L1で作れるPoC候補を確定**: クイックウィン（直リンク化）＋ブランドライブラリ再構成＋Microsoft Search設置＋メタデータ設計の4点をMVP範囲として社長承認を得る。
4. **クイックウィンの先行着手可否を判断**: 費用ゼロ・L1のため、F0完了を待たず着手してよいか社長判断。
5. **F0結果に基づき §3マッピングと §4優先度を更新**し、L2機能の採否・費用を改めて社長に上申する。
